# v7 · 尺寸固定与视觉重做

日期：2026-10-17（晚）。基准：[v6 设计稿](ui-v6/README.md)。本文记录 v7 相对 v6 的落地决策与偏差。

## 1. 两个已修复的尺寸缺陷

### 1.1 菜单栏随速率抖动

| | 修复前 | 修复后 |
| --- | --- | --- |
| 实测宽度 | **74.0 / 103.0 pt 交替** | **90.0 pt 恒定** |
| 无数据时 | `0 bps`（非规范单位） | `—` |

原因：`MenuBarExtra` 的 label 按内容固有尺寸排布，`HStack { Image; Text }` 会随文字宽度变化；`.frame(width:)` 在该位置被系统忽略（实测仍漂移 87–108 pt）。

做法：把「4 根信号柱 + 数值」整段绘制成**固定尺寸 template `NSImage`**（`MenuBarGlyph`）。数值格右对齐、等宽数字；三种显示样式各自固定宽度（72 / 38 / 15 pt 载荷，系统再加约 18 pt 边距）。

### 1.2 弹窗尺寸只增不减

实测：进入 600 pt 宽页面后返回，窗口停留在 600×650，永不回落。

最终做法（按用户要求）：**放弃宽面板，全页面统一尺寸**。

- 所有页面统一 **340×560**，含概览、设备、控制、短信、设置、首次连接、蜂窝详情。
- 数据多时向下滚动，不再撑大窗口。
- 蜂窝详情由「技术指标 / 基站与小区」两个可滚动分段承载。

> 过程中验证过 AppKit `setContentSize` 可强制双向缩放，但既然统一尺寸能满足需求，就不引入额外窗口机制。曾短暂实现的独立二级窗口已移除。

## 2. 视觉重做

### 2.1 设计令牌（`Theme.swift`）

| 类别 | 内容 |
| --- | --- |
| 间距 | `xxs 2 / xs 4 / s 8 / m 12 / l 16 / xl 22 / xxl 28` |
| 圆角 | `panel 10 / control 7 / row 7` |
| 表面 | `surface 0.035` / `surfaceHover 0.07` / `surfaceSelected accent 0.13` |
| 描边 | `hairline 0.075` / `hairlineStrong 0.12`（0.5 pt，替代 `Divider()`） |
| 动效 | `snap spring(0.28, 0.86)` / `quick easeOut(0.12)` / `page spring(0.32, 0.9)` |

修复前的实现散落着多个互不相关的 `Color.primary.opacity(0.0x)`，是画面发糊的主因。

### 2.2 组件

- `Panel`：软底 + hairline 描边。**内容必须先包进 `VStack`**——直接把背景施加到 `@ViewBuilder` 闭包会让 SwiftUI 按子视图重复背景，渲染成一张张独立卡片（这是本次实际踩到的坑）。
- `PanelHeading`：分组标题 + 可选右侧说明。
- `DisclosureRow`：悬停底色、箭头位移、图标底色三态反馈。
- `MetricCell`：支持 `contentTransition(.numericText())`；数字仍以隐藏镜像单位保持光学居中。

### 2.3 逐页

| 页面 | 变化 |
| --- | --- |
| 概览 | 蜂窝信息改为分组面板；更多设备信息带副标题 |
| 设备 | 筛选改为自绘胶囊菜单（原生 `borderlessButton` 会吃掉标签，只留箭头）；接入类型改为胶囊标签；移除无效 chevron |
| 控制 | 拆为「设备操作 / 更多」两组；未适配项加「适配中」徽标；删除永不启用的「应用更改」 |
| 短信 | 单页时隐藏分页控件；保持真实条数空态 |
| 设置 | 三组面板；自绘输入框（聚焦描边提亮）；按钮统一胶囊样式 |
| 首次连接 | 面板化表单 + 自绘输入框 + 图标化错误提示 |
| 蜂窝详情 | 统一 340 pt；两分段均改为整页滚动 |

## 3. 为什么没有引入第三方 UI 框架

评估并实测：

| 候选 | 结论 |
| --- | --- |
| Luminare（169★, BSD-3） | **编译失败**：`@Entry` 宏需要 `SwiftUIMacros` 插件，本机 Command Line Tools 不提供该插件 |
| SFSafeSymbols（1896★） | 仓库元数据与 `Package.swift`/`LICENSE` 路径均 404，无法确认可用版本 |
| Pow（4418★, MIT） | 依赖 iOS 预览框架，对本项目收益低、风险高 |

改用 **Apple 原生 API**（`glassEffect`、`GlassEffectContainer`、`glassProminent`、`contentTransition`、`symbolEffect`）+ **MiBar 的具体手法**（ultraThinMaterial 卡片、渐变 hairline、spring 参数）。

## 4. 动效与无障碍

- 页面切换、标签切换、悬停、按钮按下均有明确过渡。
- `accessibilityReduceTransparency` → 关闭玻璃，走不透明回退。
- `fhcpemGlassEnabled` 环境开关供离屏渲染器确定性渲染。
- 所有状态色点旁必有文字标签。

## 5. 验证方式

- `./script/test.sh`：20 项测试，含菜单栏宽度不变量与单位规范。
- `./script/verify-width.sh`：实时采样菜单栏与弹窗宽度，断言无变化。
- `swift run UIRender ./render/smoke` 与 `--dark`：11 张页面明暗离屏渲染，逐张目检。

## 6. 钥匙串授权弹窗（2026-10-18 修复）

**现象**：应用无休止地请求钥匙串，系统反复弹授权框。

**根因**（逐项实测确认）：

1. 应用是 **App Sandbox + ad-hoc 签名**。沙盒进程访问登录钥匙串属于跨容器访问，系统会要求授权；而 ad-hoc 签名**每次重新构建都会变**，钥匙串 ACL 随之失效，于是每次访问都要重新授权。
2. 旧的调用路径把这种访问放大成"风暴"：
   - `init()` 里无条件 `keychain.load()`；
   - 每次连接成功后又调用 `persistCredential()`，其中在"不记住"分支里执行 `keychain.delete()`；
   - `clearSavedConnection()` 同时承担"断开连接"，断开也会访问钥匙串。

**修复**：

| 位置 | 变化 |
| --- | --- |
| 启动 | **完全不读钥匙串**，启动过程零授权弹窗 |
| 连接 | 只有"记住连接"勾选状态**发生变化**时才写/删；未勾选时连接不触碰钥匙串 |
| 取回 | 设置页新增显式「从钥匙串取回」，由用户主动触发 |
| 断开 | 独立于"清除已保存连接"，断开不再访问钥匙串 |
| 失败 | 读取被拒后自动关闭"记住连接"，不重试、不循环 |

即：现在最多在用户**主动**点「从钥匙串取回」或**首次勾选**「记住连接」时，各出现一次系统授权。

## 7. 设置页移除与入口重构（2026-10-18）

按产品要求收敛为「单一面板、无独立设置页」：

| 变更 | 说明 |
| --- | --- |
| 删除设置页 | `SettingsPage.swift` 移除；连接表单成为主页面的一部分（未登录时即为该页） |
| 页脚齿轮移除 | `AppFooter` 不再有设置图标，与设计稿「齿轮+型号」的原始意图区分开，避免无效入口 |
| 控制页精简 | 移除「连接与显示设置」行，仅保留「蜂窝详情与小区」；控制页现只有 1 个导航图标 |
| 显示设置移到右键 | 菜单栏显示样式（信号与速率 / 仅信号 / 仅图标）改由右键菜单选择，左键仍只打开面板 |
| 清理测试残留 | 移除调试探针遗留的第二个菜单栏图标 |

**菜单栏交互最终形态**

| 操作 | 行为 |
| --- | --- |
| 左键 | 打开／关闭面板 |
| 右键 | 原生菜单：状态摘要、打开面板、立即刷新、显示样式三选一、退出 |
| `⌘Q` | 退出 |

**连接表单**与数据页同尺寸（340×560），不再有第二套页面尺寸。
