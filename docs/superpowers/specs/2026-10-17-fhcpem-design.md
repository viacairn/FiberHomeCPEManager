# FHCPEM 原生 macOS 菜单栏应用设计

日期：2026-10-17

状态：用户已确认总体方向；本文待审阅。本文不是已实现或已验证能力的声明。

## 1. 目标与边界

为用户拥有的 FiberHome CPE 提供直接通过局域网连接的 macOS 菜单栏应用。应用名称、可执行文件和产品名称为 FHCPEM；初始 Bundle ID 为 `local.fhcpem.app`。使用 Swift 6、SwiftUI 和必要的系统框架独立实现，不复制 MiBar 或原 Android 应用代码。旧 FiberHomeCpeManager 项目仅作为协议调查资料，不直接移植其未经验证的实现。

首个适配目标为 LG6851F；固件兼容目标覆盖 RP0106 至 RP0112。其他 FiberHome 型号通过独立适配器扩展，兼容性必须有协议证据和验证记录。不能以“FiberHome”品牌、相似版本号或相同字段名作为接口兼容的依据。

默认管理地址为 `http://192.168.8.1`，允许修改主机、端口和 HTTP/HTTPS。用户在应用中输入账号密码，不在聊天、命令参数或仓库中提供密码。

本期包含信号、在线设备、流量、重启、风扇策略、锁频段、锁小区及短信收发。不增加云账号、会员、遥测、数据库、桌面 Widget、配置文件导入导出或自动更新。最低系统目标为 macOS 14，更新系统上的原生效果按可用性适配。

## 3. 交互设计

菜单栏采用系统图标与等宽数字，默认显示连接状态及下载速率，可切换信号、双向速率或仅图标。这里的“控制栏”指 macOS 菜单栏及其弹出窗口。

小窗口以约 420 点宽度为起点，限制最大高度并允许内容滚动。使用系统材质、圆角分组、清晰文字层级和 SF Symbols，支持深浅色、键盘操作、VoiceOver 与减少动态效果。颜色之外始终用文字或图标表达状态。

| 页面 | 内容与操作 |
| --- | --- |
| 概览 | 型号、网络模式、运营商、连接状态；上下行速率；设备提供的累计流量；5G/LTE 分组显示 RSRP、RSRQ、SINR、频段、小区标识、PCI 和信道；温度与运行时间按设备能力显示 |
| 在线设备 | 名称、连接方式、IP、MAC；仅在设备提供时展示每设备速率和流量；允许展开详情 |
| 控制 | 重启；设备支持的风扇策略；自动、锁频段、锁小区三种互斥模式；应用前显示变更摘要 |
| 短信 | 设备端收件箱、分页、正文阅读和发送；发送前明确展示号码与正文；发送失败保留当前内存草稿 |

底部提供刷新、连接设置、退出。首次打开显示连接表单。详细指标在小窗口内展开，避免为了基本操作强制打开独立主窗口。

不支持与暂无数据分开表达。缺失指标显示“—”，不伪造零值；过期快照显示最后更新时间和断线提示。累计流量明确标注设备提供的周期，未知周期显示“设备累计”，不称为月套餐用量。短时速率趋势可保留在内存，退出即清空。

## 4. 软件结构与数据流

- `FHCPEMApp`：菜单栏入口、设置场景及系统集成。
- `AppStore`：主线程 UI 状态，协调刷新、登录和操作反馈。
- `DeviceSession` actor：管理会话、认证、取消和操作串行化。
- `DeviceAdapter`：型号/固件识别、认证协议、读取解析和控制编码。
- `CapabilitySet`：分别记录信号、设备、流量、风扇、频段锁、小区锁及短信的能力与限制。
- `LocalTransport`：内存 URLSession、地址验证、HTTP 响应校验及重定向限制。
- `CredentialStore`：Keychain 增删改查，不向日志暴露凭据。
- 纯值数据模型：快照、设备、无线指标、流量、短信、锁定模式和操作结果，便于独立测试。

连接流程：校验地址 → 读取设备身份 → 选择有证据的适配器 → 登录 → 使用受保护的只读请求验证认证 → 获取能力与快照 → 定时刷新。获得 Cookie 本身不代表登录成功。

打开弹窗时按约 5 秒刷新概览；关闭时约 15 秒刷新菜单栏数据。在线设备、短信等按页面进入和手动操作刷新，不重复拉取整个短信库。任何时刻仅允许一个刷新任务在途。休眠、地址切换、退出登录时取消请求；恢复后重新读取状态。失败采用有上限退避，用户可手动重试。旧连接的返回结果不得覆盖新连接状态。

速率优先使用明确单位的设备速率字段；否则以单调时间间隔计算字节计数差。计数减少按重置处理，不显示负速率或猜测溢出位宽。只解析协议明确的单位。

## 5. 控制正确性

无线锁定使用单一状态 `automatic / bandLock / cellLock / unknown`，而不是两个独立布尔开关。频段列表和小区字段校验由型号能力决定，不能在所有型号上套用固定范围。

切换流程：获取设备当前模式 → 校验输入 → 用户确认具体变更 → 如需切换则解除旧锁定 → 回读确认已解除 → 应用新锁定 → 回读并比对目标。解除失败立即停止，不继续开启另一模式。若协议支持已证实的原子切换则使用该操作。整个事务串行执行并禁止重复提交。

读回失败显示“结果待确认”，不宣称成功。外部管理后台也可能修改设备，应用每次写入前必须刷新设备状态；仅客户端 UI 互斥不能保证设备实际状态。

重启前显示会断网的确认提示。断开连接本身不能证明重启成功；有明确回执则显示已接受，否则显示结果待确认，待设备恢复后核对状态。

风扇仅提供设备已支持的模式与范围，不新增绕过温控保护的参数。短信发送和其他写操作不因超时而自动重试，避免重复发送或重复变更。认证过期时不得无条件重放写请求。

## 6. 凭据、存储与权限

凭据使用系统 Keychain，按目标地址与账号区分，不启用云同步。会话 Cookie、Token、短信、快照和趋势仅在内存；使用临时网络会话并禁用磁盘缓存，不持久化网络响应或调试报文。

默认不建立本地配置文件或数据库。为支持重启后连接，在用户选择记住连接时将连接地址、账号和密码共同保存至 Keychain；不选择时全部仅驻留内存。提供清除已保存连接的入口。显示偏好初期保持会话内有效。

应用启用 App Sandbox，只配置必要的出站网络能力及本地网络用途说明，不申请任意文件读写、下载目录、位置、联系人等权限。系统本地网络授权失败时说明如何恢复。Keychain 访问与打包签名身份需验证，不能以开发执行文件能够读写 Keychain 代替最终应用验证。

HTTPS 默认使用系统证书验证，禁止全局接受任意证书或静默降级为 HTTP。HTTP 兼容本地设备，但不把 Keychain 的静态加密描述为传输加密。阻止跨目标重定向携带认证信息，目标改变时清理旧会话。协议和地址解析不接受嵌入用户名密码的 URL。

## 7. 验证与交付标准

1. 在当前 macOS 工具链编译，生成可启动的 FHCPEM.app；检查产品名称、Bundle ID、Sandbox 和权限声明。
2. 测试协议解析、响应认证判定、流量重置、取消与过期结果隔离。
3. 使用记录请求的假设备验证互斥流程：解除失败不执行新锁定、读回不符不显示成功、重复点击不产生并发控制、超时不重复发送短信。
4. 测试 Keychain 保存、读取、更新、删除与拒绝访问时的反馈；检查持久文件和日志不含凭据或业务数据。
5. 实际打开菜单栏界面，验证登录、空值、离线、过期数据、长设备列表、短信和操作确认的布局与键盘可用性。
6. 为 LG6851F RP0106 和 RP0112 分别记录真实设备或来源明确的协议样本验证结果。仅验证一个版本不能宣称整个区间都验证通过；缺少的版本明确列为待验证。
7. 真机控制验证须使用用户在应用内输入的凭据，并由用户确认具体会造成断网或发送短信的操作。自动化验证优先使用假设备，不自行重启真实路由器。

交付包含独立源码、构建方法、可运行应用、协议证据说明及逐型号/固件兼容表。若某接口证据不足，明确记录未完成能力和所需证据，不用演示数据或禁用按钮冒充已完成的设备适配。

## 8. 设计自检

本设计保留用户要求的全部功能目标，且严格区分目标与验证状态。未增加磁盘历史、云服务或容器外存储需求；锁定切换在 UI 与会话层共同约束；敏感操作结果必须有明确证据。当前环境只有 Command Line Tools，完整打包和 SwiftUI 可用性需在实现阶段验证，不能提前承诺签名、公证或 App Store 注册已完成。
